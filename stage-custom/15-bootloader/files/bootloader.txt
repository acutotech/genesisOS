Genesis OS and the Raspberry Pi 5 bootloader
============================================

The bootloader lives in an EEPROM chip on the Pi, not on the SD card or SSD.
On the first boot of a Pi 5, genesis-eeprom.service changes a few of its
settings (from /etc/genesis/bootloader.conf) and stages the update; the
bootloader applies it at the next reboot. It runs once: what you change later
is never undone.

  sudo genesis-eeprom status        version, boot order, what Genesis did
  sudo genesis-eeprom first nvme    try NVMe first (or sd, usb, auto, keep) and apply
  sudo genesis-eeprom apply --again apply /etc/genesis/bootloader.conf again
  sudo genesis-eeprom cancel        take back a staged update before rebooting

Until the Pi that staged it reboots, the update waits on this card or drive.
Reboot that Pi before moving the card or drive to another Raspberry Pi: the
next Pi 5, Pi 500 or CM5 to boot it would take the update instead
("genesis-eeprom status" then names the Pi it came from).

A staged update you take back yourself (sudo rpi-eeprom-update -r,
rpi-eeprom-config --apply, raspi-config) stays taken back. Only one that
rpi-eeprom-update.service removed (an rpi-eeprom upgrade restarts it; status
then says "removed") is staged again at the next boot, and the reboot after
that applies it. To stop that, run "sudo genesis-eeprom cancel"; any update
applied before that reboot (rpi-eeprom-update -a, rpi-eeprom-config --apply,
raspi-config) also stands.

The boot order keeps SD card, NVMe and USB in it, so any of them boots.
"auto" puts the medium Genesis OS booted from first.

The config the bootloader had before Genesis first changed it is kept in
/var/lib/genesis/eeprom: "genesis-eeprom status" names this Pi's file on its
"Config before Genesis OS" line. That is original.conf (original.serial names
its Pi), or original-SERIAL.conf when the card or drive was set up on another
Pi since (it becomes original.conf again the next time Genesis OS changes this
Pi's bootloader). "none recorded" means Genesis OS has not changed this Pi's
bootloader; "unknown" means this Pi took another Pi's update before Genesis
saw its own config. To go back to it:

  sudo rpi-eeprom-config --apply FILE     (the file status names)

If a Pi 5 no longer boots at all, its bootloader can be reset from any
computer: in Raspberry Pi Imager choose Misc utility images > Bootloader >
SD Card Boot, write that to a spare SD card, boot the Pi from it and wait for
the green screen (or the steady green LED). That restores Raspberry Pi's
factory settings. Genesis OS on an SD card, a USB drive or an NVMe HAT+ then
boots as before; an NVMe drive on an adapter that is not HAT+ is found again
only once PCIE_PROBE=1 is back: boot Genesis OS from an SD card, run
"sudo genesis-eeprom first nvme", reboot, and remove the card.
